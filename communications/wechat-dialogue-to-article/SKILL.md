# 将讨论对话整理成微信公众号文章

把原始对话视为思想素材，而不是需要逐句缩写的文本。保留讨论中最有生命力的经验、分歧和追问，重新建立一条适合阅读的论述主线。

## 默认写作取向

遵守以下优先级：

1. 深度胜过面面俱到。
2. 清晰的个人判断胜过中性的会议纪要。
3. 解释机制胜过复述观点。
4. 具体经验胜过抽象口号。
5. 诚实呈现复杂性胜过制造确定感。
6. 对读者有启发胜过追求传播套路。

将文章写得真诚、克制、有观点、有个人声音。让读者感到作者确实经历过思考，而不是由一个旁观者把信息排列整齐。

## 工作流程

### 1. 建立素材地图

完整阅读对话，先在内部识别：

- 讨论缘起和真实问题；
- 反复出现的主题；
- 最有价值的事实、经历、例子和原话；
- 观点之间的分歧、转折和未解决的问题；
- 哪个认识在讨论过程中发生了变化；
- 哪些内容只是寒暄、重复、跑题或口头填充。

不要立即按对话顺序改写。除非用户明确要求，最终文章不要保留问答体或“甲说、乙说”的流水账结构。

### 2. 确立唯一主线

用一句话写出文章核心判断，作为内部写作准绳。它必须包含有辨识度的判断，而不只是主题名称。

优先选择具备以下特征的主线：

- 对话里存在真实张力或反常识之处；
- 能解释“为什么会这样”，而不只是描述“发生了什么”；
- 与人的选择、组织方式、技术变化或日常经验有关；
- 能从具体讨论延伸出可迁移的认识。

如果素材支持多个方向，选择最有张力且证据最充分的一条，其余内容作为支线或舍弃。不要把数篇文章硬塞进一篇。

### 3. 推进深度洞察

沿以下阶梯思考，但不要机械地把阶梯名称写进正文：

1. **现象**：大家实际观察到了什么？
2. **矛盾**：表面解释为什么不够？哪两种合理诉求彼此冲突？
3. **机制**：什么激励、约束、认知偏差、权力关系或系统结构造成了它？
4. **二阶影响**：这种机制继续运行，会改变谁的行为，又会带来什么间接后果？
5. **边界**：这个判断在什么条件下成立？有什么反例或代价？
6. **迁移**：它还能帮助读者理解哪些相似处境或作出什么不同选择？

深度必须由素材和推理支撑。不要为了显得深刻而拔高、发明因果、套用宏大叙事或堆砌“本质”“底层逻辑”“时代”等词。

### 4. 重建文章结构

根据素材自然安排结构，默认使用以下叙事弧线：

1. 用一个具体场景、尖锐问题、意外发现或有张力的判断开篇；
2. 交代问题为何值得讨论，但迅速进入核心；
3. 用对话中的经历、例子和分歧逐步展开；
4. 从现象进入机制，提出文章最重要的洞察；
5. 主动处理反面观点、限制条件或现实代价；
6. 回到人的处境，以余味、问题或可执行的判断收束。

不要使用固定的“提出问题—分析问题—解决问题”模板。小标题只在能推动论述时使用，通常控制在 2–5 个；标题之间要有思想递进，避免把文章切成清单。

### 5. 写成作者的声音

- 默认使用自然的第一人称“我”承接观察和判断；多人共同观点可谨慎使用“我们”。
- 保留对话中的犹豫、修正和认识变化，让结论显得经过思考而非凭空宣布。
- 句子以短句和中等长度句为主，长短交替；一个自然段集中表达一个意思。
- 语言准确、具体、平实。需要术语时立即用普通话解释。
- 可以有文学感，但不要持续抒情；可以有锋芒，但不要刻意冒犯。
- 用例子承载观点，用判断连接例子。不要连续堆叠金句。
- 让转折来自逻辑，不依赖大量“然而”“值得注意的是”“由此可见”。
- 保留必要留白，不把每一个结论解释到失去余味。

### 6. 执行内容取舍

保留：

- 能改变读者理解的关键事实；
- 具体、有细节、有处境感的经历；
- 暴露矛盾或推动认识变化的分歧；
- 简洁且具有个人特征的原话；
- 能支持核心判断的反例与边界。

删除或压缩：

- 寒暄、重复确认、口头禅和无关支线；
- 只显示“聊了很多”却不推动文章的内容；
- 同义反复和为了凑篇幅加入的背景知识；
- 与核心主线无关、即使正确也无必要的知识点。

当素材不足时，缩小文章命题或写成短文，不要用空泛段落补齐长度。

## 事实与人物处理

- 不编造事实、案例、数字、出处、对话或作者经历。
- 可以润色原话，但不得改变原意；若使用引号，只放确实来自素材且可忠实还原的话。
- 区分事实、对话参与者的判断和文章作者的推论，不把猜测写成定论。
- 未经允许，删除或泛化私人姓名、单位、联系方式和可识别细节。
- 遇到关键事实冲突或明显缺口时，优先写出不依赖该事实的版本；只有当缺口会根本改变主线时才向用户确认。
- 用户要求查证或补充外部材料时，单独核验并标明来源；不要让外部材料淹没原始对话。

## 避免 AI 腔和营销腔

禁止默认使用以下写法：

- “在这个快速变化的时代”“随着……不断发展”等空泛开场；
- “首先、其次、再次、最后”驱动整篇文章；
- “不仅……更……”连续排比；
- “值得注意的是”“不难发现”“归根结底”等无信息连接词；
- “赋能、破局、重塑、颠覆、底层逻辑、认知升级”等未经解释的概念；
- 为制造戏剧性而使用“震惊”“彻底改变”“所有人都错了”；
- 每段末尾都下结论、每节都制造金句；
- 虚构“有人问我”“我突然意识到”等场景；
- 对读者说教，或用居高临下的口吻给出人生答案。

删掉任何放在别的文章里也成立的句子。若一句话只显得正确却没有增加认识，重写或删除。

## 标题与开头

标题要准确承载文章中的张力或判断，不制造正文无法兑现的悬念。优先考虑：

- 一个具体而反常识的判断；
- 两种力量之间的冲突；
- 一个读完文章后会获得新答案的问题；
- 对话中最有辨识度的短句，经忠实提炼后使用。

开头应在前 150 字内让读者知道“发生了什么”或“真正的问题是什么”。不要先写大段时代背景，也不要用辞典式定义起笔。

## 默认交付格式

除非用户指定其他形式，输出：

1. 3 个标题候选，将最推荐的放在第一位；
2. 一句 50–100 字的公众号摘要；
3. 可直接发布的 Markdown 正文；
4. 仅在确有必要时，另列不进入正文的“待确认信息”。

正文长度服从素材，不硬凑字数。默认不解释写作过程，不附素材地图、推理阶梯或修改说明。

## 完稿检查

交付前静默检查：

- 能否用一句话说清文章独有的核心判断？
- 每一节是否都在推动这条主线？
- 洞察是否至少解释了一层机制，并包含必要边界？
- 具体例子是否足以支撑重要判断？
- 是否误把参与者观点写成事实，或创造了素材中不存在的经历？
- 是否仍有套话、同义反复、清单感、说教感或过度拔高？
- 开头是否迅速进入问题，结尾是否留下真实余味？
- 标题承诺的内容是否在正文中得到兑现？

发现问题时直接修订，再输出成稿。
