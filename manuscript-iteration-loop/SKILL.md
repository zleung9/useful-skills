# Multi-Model Manuscript Iteration Loop

将多个前沿模型（Claude、GPT、Gemini 等）的输出融合为一篇最佳手稿的七步四版本工作流。

---

## Why This Skill Exists

单一 AI 模型有自己的语言习惯、修辞偏好和盲点。当风险很高时——Nature 投稿、重要基金申请、董事会备忘录——没有任何一个模型的输出应该被视为最终版本。

这个 skill 编码了一个**七步四版本**工作流，从多个前沿模型的输出融合成一篇最佳手稿。它源自 2026 年 4 月一篇 Nature 目标论文的真实迭代（领域是锂金属电解质，但工作流本身是**领域无关**的——同样适用于流行病学基金提案、哲学评论文章、产品策略备忘录）。

---

## Core Principles

在运行循环之前，内化这五条原则。如果某一步感觉乏味，其中一条是它仍然值得做的原因。

1. **分层收敛。** 每个版本锁定一个粒度：V1 = 逻辑链，V2 = 句结构，V3 = 用词，V4 = 长度+格式。永远不要在一次迭代中"改善一切"——你会过度适应上一个模型的语气。
2. **多模型多样性。** 始终至少运行三个前沿模型进行并行打稿和评分。单一模型的输出是单一分布的单一样本；三个模型暴露真正的信号在哪里。
3. **人类做选择，不做创作。** 用户在 V1→V4 的主要工作是回答多选题（"选 A、B、C，还是重写？"），而不是从头写作。这既利用了模型，又让用户的判断成为最终过滤器。
4. **可量化锚点。** 把"这好吗？"替换成一个模型可以承诺的具体数字问题。锚点应该是模型能够附以理由地分配数字的东西。
5. **句子级粒度优于全文粒度。** 对每个句子评分，而不是对整个摘要评分。这使得可以从每个模型中挑选最佳句子，组装出一个严格优于任何单一模型输出的"弗兰肯斯坦"草稿。

---

## When to Trigger This Skill

触发完整循环当**所有三个**条件都满足时：

- **风险足够高**（通常 3-10 小时的人力+AI 时间，跨越数天）。Nature 投稿、重要基金 LOI、CEO 主题演讲、同行评审的书章、法律文件。
- **产出是基于文本的**（手稿、论文、提案、长备忘录）。不适用于代码、电子表格、幻灯片或一次性邮件。
- **用户可以访问至少两个 AI 模型**（循环可以优雅地降级到两个，但最好三个以上）。

如果用户随口问"你能润色这段话吗？"——**不要触发完整循环**，直接做润色。循环是为深思熟虑的多会话工作设计的。

## Entry 判断

用户与我开始对话时有四种方式。我从用户的开场白中检测是哪一种，并分别不同地回应。

### Entry 1 — 新手稿，无先前工作

**信号：** "我想开始一个手稿迭代……"、"我有一份想为 Nature 润色的草稿"、"帮我迭代这个基金提案"，或只是上传了一份草稿但意图不明。

**我的回应：** 我承认请求，然后**按顺序**提出五个 Step-0 问题（不是一次全部）：

1. 目标期刊是什么，你目前估计的投稿/接收概率是多少？
2. 你团队的资质，以及期刊会通过什么背景来阅读你？
3. 你对当前草稿的具体担忧是什么——让你夜不能寐的那件事？
4. 你可以使用哪些其他 AI 模型来进行并行打稿和评分阶段？
5. 你是否可以在接下来 1-2 周内投入 5+ 小时的注意力？

收集答案。如果任何答案揭示这个循环不适合这个用户（例如，他们只有 Claude，或者只有 30 分钟），我会说出来并提供更简单的线性编辑路径。

如果答案都符合，我就帮助用户编写 Step 0 策略咨询提示（见 `references/prompt-templates.md` § Step 0），然后让他们将其粘贴到每个可用模型中。

### Entry 2 — 继续先前的迭代

**信号：** 上传了一个版本跟踪文档，或者用户说"我们在 V2，去 V3"，或者"我从模型那里收到了三个草稿"。

**我的回应：** 我仔细阅读跟踪器——不只是最新版本，而是完整的历史和注释。我重构：我们现在在哪一步，量化锚点是什么，目标期刊是什么，当前最佳模型是什么，还有什么问题。

然后我用一段话向用户总结状态并确认："我们在 Step [N]。锚点是 [X]。当前最佳模型是 [Y]。下一个行动是 [Z]。这与你的理解一致吗，或者你想纠正我吗？"

在用户确认状态之前我不会继续。

### Entry 3 — 单一步骤的角色扮演

**信号：** "你能为这三个草稿评分吗？"、"你能扮演 Step 3 的评分者吗？"、"这是 V2，给我五个措辞建议"——即用户希望我扮演一个步骤的角色而不运行完整循环。

**我的回应：** 我完全按照该步骤的提示模板扮演请求的角色（来自 `references/prompt-templates.md`）。我不会主动提供运行其他步骤，也不会问关于更大循环的元问题，也不会建议"我们真的应该从 Step 0 开始"。

但如果用户请求的角色**在给定的循环状态下是不连贯的**（例如，他们想润色一个逻辑明显broken的草稿的措辞），我会 flag 一次，然后做他们要求的。flag 一次是诚实；反复争论是阻碍。

### Entry 4 — 超出入范围

**信号：** "帮我写一封求职信"、"你能起草一封电子邮件吗？"、"快速润色这段话"、"就告诉我这听起来好不好。"

**我的回应：** "这不是合适的工具——循环是为那些证明合理投入 5+ 小时结构化工作的手稿设计的。对于你所问的，常规的 Claude 对话会更好地服务你。"然后我移交并关闭会话。

## The Seven-Step Loop

循环产生四个版本。每一步的输出成为下一步的输入。始终记录哪个 AI 模型的输出被传递——这创建了审计追踪。

```
用户输入
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 0 — 策略咨询（上游诊断）                                 │
│  让每个可用模型诊断手稿的定位和策略                              │
│  → 2-4个战略角度 + 概率估计，用户选择一个                        │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 1 — V1 逻辑草稿（用户手写）                              │
│  锁定逻辑链。混合语言+故意不润色的大纲。                          │
│  Claude 审查逻辑漏洞，不翻译不润色。                              │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 2 — 并行流畅草稿（每个模型独立）                           │
│  每个模型将 V1 转化为流畅的、符合期刊风格的草稿                    │
│  → N份完整草稿（通常 N=3），每个标注来源模型                      │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 3 — 多模型句子级评分（背靠背批评）                         │
│  每个模型扮演量化锚点评委，对所有草稿逐句评分                       │
│  → 句子级评分矩阵 + 识别"最佳模型"                              │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 4 — V2 句结构版本（人类组装）                            │
│  用户基于评分矩阵逐句选择，拼装 V2                                │
│  → V2：结构锁定                                               │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 5 — V3 措辞版本（最佳模型，N点精修+闭环评分）               │
│  锁定用词。仅粒度词汇润色，不碰结构或逻辑。                        │
│  → V3：用词锁定                                               │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 6 — V4 最终润色（长度+格式）                              │
│  最终长度和格式校准。不再改变逻辑、结构或用词。                    │
│  → V4：最终手稿                                               │
└─────────────────────────────────────────────────────────────┘
```

## Step 0 — 策略咨询

**目的：** 在起草一个词之前，让每个可用模型诊断手稿的定位和策略。这暴露出在框架中的盲点（目标期刊不匹配、核心主张弱、缺少反证），否则会破坏每个下游版本。

**输入：** 当前草稿 + 用户声明的目标（期刊、受众、目标）+ 用户声明的担忧。

**输出：** 2-4 个战略角度的短名单（带概率估计），由用户选择。从现在起，每个版本都为选定的角度服务。

见 `references/prompt-templates.md` § Step 0 获取确切的提示框架。

---

## Step 1 — V1 逻辑草稿

**目的：** 锁定逻辑链。在这个阶段，流利的英语（或目标语言）是主动有害的——它诱使模型专注于润色而不是结构。

**用户做什么：** 将 V1 写成一个**混合语言、故意不润色的大纲**，突出逻辑骨架。对于非英语母语者，预期模式是：英语用于技术术语和关键框架（他们想保留的），母语用于连接部分——例如："Electrochemical energy system is inherently cross-scale, 理解这一关联成为...的核心问题, 但是 A more fundamental question remains: 哪个更可信？"

**为什么混合语言：** 它向下游模型发出信号："翻译我的逻辑，不要质疑它。"如果 V1 已经是流利英语，模型会将其视为近乎最终版本，只在局部润色，从不重新结构化——即使逻辑要求这样做。

**Claude 做什么：** 审查 V1 的逻辑漏洞、冗余和缺失的连接部分。提澄清问题。**还不要**翻译或润色——那是 Step 2。

**输出：** V1 逻辑草稿，被用户确认为逻辑完整。

---

## Step 2 — 并行流畅草稿

**目的：** 让每个模型分别将 V1 转化为流畅的、符合期刊风格的草稿。

**用户做什么：** 将相同的提示粘贴到每个模型中，收集输出原文，并按模型标注。

**输出：** N 份完整草稿（通常 N=3），每份标注其来源模型。

见 `references/prompt-templates.md` § Step 2。

---

## Step 3 — 多模型句子级评分

**目的：** 识别手稿每个槽位的最强句子，以及总体最强的模型。这是工作流的核心。

**关键：** 每个模型对所有草稿评分，包括自己的。自评是被鼓励的——一个模型愿意在自己的句子不如另一个模型的句子时贬低自己的句子，这是真实信号，不是噪音。

**输出：** （a）句子级评分矩阵，（b）识别的"最佳模型"用于 Step 5 和 6。

见 `references/scoring-rubric.md` 获取完整的评分矩阵结构。
见 `references/prompt-templates.md` § Step 3 获取评分者提示模板。

---

## Step 4 — V2 句结构版本

**目的：** 锁定句子的选择和结构。用户通过在评分矩阵的指导下做出句子级选择来组装 V2。

**对于每个句子槽：** 提出三个候选 + 三个评分理由三元组，并问用户："你想要哪个——A、B、C，还是重写？"

**用户选择后：** 记录选定的句子 + 简短理由到版本跟踪器。

**输出：** V2——结构锁定，句子由用户选择或重写。

---

## Step 5 — V3 措辞版本

**目的：** 锁定用词。细粒度词汇润色，不碰结构或逻辑。

**最佳模型做什么（或 Claude 如果是最佳模型）：** 审查 V2 并提出**恰好 N 个具体用词更改**（通常 N=5）。格式：

```
Proposal #N: [short descriptive name]
- Current: "[exact text]"
- Proposed: "[exact replacement]"
- Reason: [2–4 sentences — what reviewer-attack-surface does this close?]
- Estimated impact: [+X.X percentage points on anchor]
```

**"Estimated impact" 字段是闭环**——它强制模型承诺一个它将在下一轮中被追究的预测。

**用户做什么：** 对每个提案选择：**接受 / 拒绝 / 接受并修改**。逐个literal多选交互；用户不写正文。

**输出：** V3——用词锁定。

见 `references/prompt-templates.md` § Step 5。

---

## Step 6 — V4 最终润色

**目的：** 最终长度和格式校准针对期刊规范。不再逻辑、结构或用词更改——只有长度修剪和格式对齐。

**输出：** V4——最终手稿。

见 `references/prompt-templates.md` § Step 6。

## 版本跟踪器

**这是循环的记忆。** 版本跟踪器是跨会话状态的主要来源。

### 版本跟踪器模板

见 `assets/version-tracker-template.md` 获取完整模板。

核心原则：**最新在最上，旧版本堆叠在下。**

```
V4 — FINAL（最新，最上）
V3 — 用词锁定
V2 — 句结构锁定
V1 — 逻辑链
Step 0 — 策略咨询
```

### 版本跟踪器必须始终包含的四个字段

```
Target venue: [期刊]
Quantifiable anchor: [量化锚点]
Current status: [当前状态]
Best model (current): [当前最佳模型]
```

### 追踪器存放位置

- **可访问**给所有相关人员（用户、任何合著者、未来在新对话中的 Claude）
- **不随意编辑。** 每次编辑应可追溯到某一步骤。
- **上下文重置时复制到新对话。** 新的 Claude 实例在新对话中没有先前会话循环状态的记忆。

## 关键反模式

见 `references/anti-patterns.md` 了解十个常见失败模式。最需要警惕的三个：

1. **用户在 V2 开始后继续编辑 V1。** 停止循环，告诉他们原因，让他们选择：回滚 V2 并重跑，或在 Step 5 吸收编辑。不要两者兼有。
2. **最佳模型在多轮中悄悄地将其余模型的句子替换为自己的语气。** 检查每个提案——如果来自不同模型的句子被没有命名理由地重写，flag 它并建议拒绝。
3. **每轮产生 ≤1 个百分点的估计改进。** 宣布停止规则并询问用户是否已达到上限。

---

## 最终交付

当 V4 锁定时，做三件事：

1. **生成最终干净文档。** 没有注释的 V4 版本，可直接粘贴到投稿系统。
2. **生成审计摘要。** 一页文档回答：我们选择了什么角度，量化锚点是什么，最佳模型是什么，每个版本的累计百分点增益是多少，最大的被拒绝提案是什么以及为什么。
3. **告诉用户我完成了。** "V4 已锁定。在文本层面进一步迭代不太可能有帮助——到你目标期刊的剩余差距在于 [数据质量 / 新颖性 / 范围]。我建议投稿。祝你好运。"

然后停止。不建议 V5。不建议另一轮。如果用户想在审稿人意见后回来进行修改循环，那是新会话和新循环——不是这个的延续。
